Launch Dispatch · v0.2.0

Voice dictation that
stays on your machine.

After two months of fork-and-build, handy v0.2.0 ships today — a Wispr-Flow-class voice tool that runs entirely on your laptop, distributed direct from the maintainers, free forever. No cloud middleman. No subscription. No API key.

By the handy maintainers · 28 May 2026 · 7 min read

Hold a hotkey anywhere on your computer, speak naturally, and clean formatted text is pasted at your cursor — that's the entire pitch. The difference is where the work happens. Cloud dictation apps stream your audio to a remote server, charge a subscription, and quietly retain transcripts. handy does the same thing on your own hardware, costs nothing, and the audio file never leaves /tmp.

Version 0.2.0 is the first build worth handing to a stranger. The white-screen-on-AMD bug is gone. The Whisper Tiny model ships in the installer so first-use latency is < 1 second on a typical x86_64 CPU. The floating widget restores focus correctly so transcripts land in the editor you were just typing in, not in handy's own window. The dedicated GPU is auto-picked over the integrated one on dual-GPU laptops without configuration.

The interesting part isn't any single feature — it's that all of them run without a single outbound network call. The privacy guarantee isn't a promise, it's a whitelist, hard-coded in Rust: the network client physically cannot dial anything outside 127.0.0.1.

II.

The widget that follows you around

handy can be invisible — global hotkey only, no UI in your way. Or it can run as a small floating pill at the corner of your screen, the way Wispr Flow's "Flow Bar" works. The pill is opt-in, draggable, fades when idle, and lights up when listening. You can click it to start dictation instead of holding the hotkey, which is useful when your hands are off the keyboard or you're running a video call.

The animation to the right shows the three states the widget cycles through: idle (faded, waiting), listening (violet pulse with elapsed seconds), and processing (muted, with a spinner while Whisper crunches the audio).

In v0.2.0 the widget gained a small but important fix: clicking it no longer steals the paste target. handy snapshots the foreground window before the click registers, then restores it right before typing — so the transcript lands in the editor you were just in, not in the handy window that the click accidentally focused.

IV.

The hardware question

The most reported install-day gotcha for local dictation on Windows laptops is the wrong GPU. ggml's Vulkan backend enumerates devices in driver order, which on most laptops puts the integrated iGPU at index 0 — even when a discrete dGPU is sitting right there, idle, with five times the throughput.

v0.2.0 fixes this in two places. The library-side auto-selector (auto_select_gpu_device in transcribe-rs) explicitly prefers discrete over integrated, then uses total VRAM as a tiebreaker. The UI-side dropdown now shows each device with its kind tag — "— Dedicated" or "— Integrated" — and sorts discrete cards to the top of the list, so you can tell at a glance which one Auto will pick.

If you only have an integrated GPU, nothing changes — Auto still picks the iGPU, and the "Auto" label simplifies back to plain text instead of "Auto (Dedicated GPU)". Zero-config on every machine.

V.

The wire test

// src-tauri/src/llm_client.rs
fn validate_local_url(url: &str) -> Result<(), Error> {
  const ALLOWED: &[&str] = &[
    "127.0.0.1",
    "::1",
    "localhost",
    "apple-intelligence://",
    "phi-silica://",
  ];
  // reject anything else — at the wire
  if !ALLOWED.iter().any(|a| url.starts_with(a)) {
    return Err(Error::NonLocalUrl);
  }
  Ok(())
}

The function above is the chokepoint. Every LLM API call in handy — Auto Cleanup, Command Mode, Transforms — passes through it. If the base URL doesn't start with one of those five strings, the request is rejected before a socket opens.

The cloud LLM integrations that came with the upstream Handy fork — OpenAI, Anthropic, Groq, Cerebras, OpenRouter — were physically removed in Phase 1.10. Existing settings files that reference them migrate to local defaults on first launch.

Two outbound calls remain, both opt-out: one-time model download from Hugging Face on first run, and version checks against the GitHub Releases page. Neither carries audio or transcripts. Pull the network cable after install and dictation keeps working forever.

VII.

Questions worth answering

Is it actually 100% local? What does it phone home?

Yes. The whitelist in Section V is the chokepoint — every network call goes through it. Two outbound calls remain, both opt-out: model download from Hugging Face on first run, and update checks against this repo's Releases page. Neither carries audio or transcripts.

How is it free? Where's the catch?

No catch. handy is a fork of cjpais/Handy (MIT) with Wispr-Flow-class features layered on top. Distribution is GitHub Releases only — no app stores, no payments, no usage metering. If you want to support it, file an issue or send a PR upstream.

How fast is transcription on a typical machine?

Whisper Tiny ships bundled — short clips (under 10 seconds) transcribe in well under a second on a typical x86_64 CPU. Larger models (Small, Medium, Turbo) auto-download on demand based on your hardware tier. On a machine with a dedicated GPU, Vulkan / Metal / CUDA acceleration is typically 5–30× faster than CPU.

My laptop has two GPUs. Which one does handy use?

The dedicated one — see Section IV. handy auto-selects discrete GPUs over integrated ones and uses total VRAM as a tiebreaker. You can override in Settings → Advanced → Performance → GPU device.

Does it work in IDEs and coding agents?

Yes — there's a Vibe Coding mode that activates in Cursor / VS Code / Windsurf / JetBrains IDEs and in terminal-hosted coding agents like Claude Code and Codex. It file-tags ("tag main.py" → @main.py) and wraps identifiers in backticks ("the user settings" → `userSettings`). Disabled outside those contexts so your prose stays clean.

Can I use it offline?

Once installed and the first model is downloaded — yes, fully. handy doesn't need internet for any feature except checking for app updates. Pull the network cable and it keeps transcribing.

Are the builds signed?

Not yet — code signing is on the roadmap but not gating the v0.2.0 release. You'll see a one-time "Run anyway" warning on first launch (SmartScreen on Windows, Gatekeeper on macOS). The published checksums let you verify the binary matches what was built in CI.
